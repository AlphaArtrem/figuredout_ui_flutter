# figuredout_ui

The Flutter design system for FiguredOut apps — the sibling of the React package
`@figuredout/ui-web`. Same visual language, same rules, same documentation surface.
Widgetbook plays the role Storybook plays there.

> **Status: phases 0–2 complete.** Tokens, theme and the Widgetbook Foundations surface are
> in. Components (`lib/src/primitives/`, `patterns/`, `charts/`) land in phases 3–6, and the
> full doc set — `AGENTS.md`, `COMPONENT_GUIDE.md`, `docs/components.md`,
> `docs/migrating-from-luxe.md`, `components.manifest.json` — in phase 7.

## What is here

| | |
| --- | --- |
| `lib/src/tokens/` | `FoTokens` (the only file allowed to hold a literal), `FoColors`, `FoTextStyles`, `FoShadows`, `FoMotion`, `FoLayout`, `FoChartColors` |
| `lib/src/theme/` | `FoTheme.light()` / `.dark()`, `FoThemeExt`, `FoWindowClass`, and the `context.fo*` extension |
| `lib/fonts/` | Geist and Geist Mono static weights, bundled rather than fetched |
| `widgetbook/` | A separate package — the live surface, and the only thing that compiles the use cases |
| `docs/contrast-report.md` | Generated by `test/tokens/contrast_test.dart`; never edited by hand |

## Using it

```dart
MaterialApp(
  theme: FoTheme.light(),
  darkTheme: FoTheme.dark(),
  home: const HomeScreen(),
);
```

Inside a widget, reach design values through the context extension — never through
`FoTokens` directly, or the widget will not follow a theme switch:

```dart
Container(
  padding: EdgeInsets.all(context.foSpacing.lg),
  decoration: BoxDecoration(
    color: context.foColors.surface,
    borderRadius: BorderRadius.circular(context.foRadii.card),
    boxShadow: context.foShadows.raised,
  ),
  // A hairline goes in foregroundDecoration, never decoration.border — a
  // ClipRRect-clipped child that paints a full-bleed band covers the parent's
  // border along that edge.
  foregroundDecoration: BoxDecoration(
    borderRadius: BorderRadius.circular(context.foRadii.card),
    border: Border.all(color: context.foColors.edge),
  ),
  child: Text('Hello', style: context.foText.body),
);
```

## The surface ladder

Four steps, in both themes. **Which surface a thing sits on is its meaning, not a
preference.**

| Token | What sits on it |
| --- | --- |
| `surfaceSunken` | Holes: text fields, segmented-control tracks, wells |
| `bg` | The page itself |
| `surface` | Cards, tables, panels — anything resting on the page |
| `surfaceRaised` | Anything lifted: a dialog, a menu, a toast, a hovered row, an open tile |

White is the **top** of that ladder in light mode, not the resting surface. A card on
`surface` separates from the page without leaning on its hairline, which is what leaves
`surfaceRaised` free to mean lifted. Migrating code that used a white `surface` to mean
"lifted above the page" must be re-pointed at `surfaceRaised`.

## The five rules

1. **A hairline is a foreground decoration, never `decoration.border`.** On a container
   whose child paints a full-bleed band, a border is painted underneath it.
2. **Three elevation steps, no more.** `FoShadows.raised` rests, `.hover` is picked up,
   `.overlay` covers something else. Never `Material(elevation:)`, never `Card(elevation:)`,
   never a black shadow.
3. **Mono uppercase captions name values; mono tabular figures are values.** A form label
   instructs rather than names, so it stays sentence-case semibold sans.
4. **One duration and one curve**: `FoMotion.normal` with `FoMotion.standard`, or
   `FoMotion.fast` under 200ms.
5. **One focus treatment**: a 4dp ring in `focusRing`.

## Validation

```bash
flutter analyze && flutter test && dart format --output=none --set-exit-if-changed .
```

```bash
cd widgetbook && dart run build_runner build -d && flutter build web --release
```

The Widgetbook web build is not optional. `flutter analyze` on the library does not compile
the use cases, so a use case can be broken while the package is green — it is the exact
Flutter twin of the web package's "`tsc` does not check the stories".

Two tests carry rules the analyzer cannot:

- `test/tokens/contrast_test.dart` — WCAG ratios for every semantic ink, in both themes,
  **and against its `-soft` companion composited over the surface**. That composite is what
  a badge produces, and it is where the web package found `--color-success` failing AA. On
  a pass it rewrites `docs/contrast-report.md`, so the report can never go stale.
- `test/tokens/no_literals_test.dart` — bans `Color(0x`, `Colors.*` (except `transparent`),
  `Duration(`, `Curves.easeInOut`, `Curves.linear` and non-zero `elevation:` everywhere
  under `lib/src/` except `lib/src/tokens/`.

## Fonts

Geist and Geist Mono ([OFL-1.1](lib/fonts/OFL.txt), from
[vercel/geist-font](https://github.com/vercel/geist-font) v1.7.2) are vendored as static
weights — 400/500/600/700 sans, 400/500 mono — rather than fetched, because the consuming
apps are offline-first.

Every style in `fo_typography.dart` passes `package: 'figuredout_ui'` alongside its family.
Without it the family resolves against the *consuming app's* font manifest and falls back
to Roboto with no warning — invisible from inside this package, which is why
`test/theme/fo_theme_test.dart` asserts it.
